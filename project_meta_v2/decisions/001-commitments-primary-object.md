# 001 — Commitments Are the Primary Product Object

Status: **Accepted**

## Decision

Revoke 2.0 is organized around Commitments rather than user-created schedules/regimes.

Schedules remain enforcement primitives generated from commitments.

## Consequences

- onboarding asks what the user wants to change, not which schedule they want to build;
- tapering becomes core Reduce behavior;
- Time Block and Usage Limit become Protect/enforcement mechanisms;
- Home centers progress/adherence rather than schedule inventory;
- backend needs an immutable commitment activation snapshot over time.
